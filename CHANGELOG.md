# Changelog

## Unreleased

- Deposit and Withdraw moved from the header bar into the account menu (the address button), above Copy address and Disconnect; Portfolio keeps both buttons. The header now shows only the cash amount and the account button. The Withdraw dialog's network and token pickers are a themed dropdown (`src/components/Select.tsx`) instead of native selects: token names as hints, short contract address when two tokens share a symbol, keyboard support, and a list that is not clipped by the dialog.
- Withdraw: a **Withdraw** button next to Deposit (header and Portfolio) sends pUSD from the trading wallet through Polymarket's bridge to an address on Polygon, Ethereum, Base, Arbitrum, Optimism or BNB Smart Chain, in the token you pick. It shows the bridge's estimate and fees, then a review with the full recipient. New routes `GET /api/withdraw` (balance, path, destinations), `POST /api/withdraw/quote` and `POST /api/withdraw` (a `withdraw` wallet operation in wallet mode). New error codes `UNSUPPORTED_DESTINATION`, `INVALID_RECIPIENT`, `INVALID_AMOUNT`, `BELOW_MINIMUM` (400), `INSUFFICIENT_BALANCE`, `WITHDRAW_IN_PROGRESS` (409), `QUOTE_UNAVAILABLE` (502). Every check runs before the bridge address is requested and before anything is sent.
- Phase 11: the app now matches the design canvas. Navigation is Markets · Portfolio · Alerts · Automation (market pages show a breadcrumb); the header shows the cash amount, a Deposit button and an account menu on every page, and no longer shows the access chip. Trade ticket tabs are Market | Limit | Pro (take-profit, stop-loss and TWAP moved into Pro); order book and trades fill the column; order confirmation shows a BUY/SELL tag and a success toast. Markets has a featured card with a one-week chart and Buy links that preselect the outcome. Enable trading and Deposit are dialogs; in wallet mode Enable trading shows which transaction is waiting. Alerts and Automation pages are redesigned. Shortcut `g m` (Markets) replaces `g b`. Emoji icons replaced with line icons.
- Phase 10: connect a browser wallet instead of keeping a key on disk. With `POLYMARKET_PRIVATE_KEY` blank the app is in wallet mode: pick an EIP-6963 wallet, sign "Sign in to Polymarket" once, then the browser signs each order and transaction while the server keeps the session and API credentials in memory (HttpOnly cookie, one session, one operation at a time). Key mode is unchanged; the two are exclusive. New routes `/api/wallet/{session,ops}`; new error codes `WALLET_NOT_CONNECTED` (401), `NEEDS_POL` (409), `AUTOMATION_NEEDS_KEY` (403), `KEY_MODE` (409), `OP_IN_PROGRESS` (409), `USER_REJECTED` (403), `ACCOUNT_LOOKUP_FAILED` (503), `CONNECT_FAILED` (500).
- `POLYMARKET_WALLET_ADDRESS` is now optional: the account wallet is found from the key's Polymarket profile, else the key's own address as a plain EOA account. The source is shown in the header and the Deposit dialog. The app never deploys a Deposit Wallet implicitly.
- `POLYMARKET_RELAYER_API_KEY` is now optional. Without it, EOA accounts pay POL for Enable trading and Redeem (about 0.2 POL recommended, 0.02 minimum); Safe and Deposit Wallet accounts do those on polymarket.com. Key-mode EOA accounts use the POL path even when a relayer key is set.
- Automation (take-profit, stop-loss, TWAP) works in key mode only.
- Deposit dialog shows a QR code of the bridge address (`uqr`, black on white; round-trip tested with `jsqr`, a dev dependency).
- The root layout is now rendered per request, because the signing mode is read at request time.
- README: two ways to sign, account types, relayer key guidance, and a VPS guide (AWS EC2, SSH tunnel, systemd) with a jurisdiction warning.
- Phase 9 redesign: a dark trading-terminal look (graphite surfaces, mint Yes, coral No, Inter and JetBrains Mono from local font stacks), a new header with active nav, ⌘K hint, access chip, cash and wallet chips; three-column trade page (outcome rail with probability bars, chart, depth-bar order book, segmented ticket); browse with a featured event and card grid; portfolio with KPI tiles and tabs; restyled alerts and automation pages. The event page now opens on its top outcome.
- Watchlist: star events and outcomes; a Browse sidebar card shows live prices and the change since starred (browser-only).
- Keyboard shortcuts: ⌘K//, g-chords, b/s/y/n on the ticket, ? help with an on/off switch. Shortcuts never place or confirm orders and do nothing while a dialog is open.
- Export CSV on every Portfolio tab (all pages, up to 2,000 rows, formula-injection safe).
- Deposit dialog (`POST /api/deposit`): shows the account wallet's Polymarket bridge address for USDC/USDC.e on Polygon with the live minimum; the app never sends funds. The balance tile no longer shows the account wallet's full address.
- Phase 8: limit orders can expire (GTD: 1 hour, 1 day, 1 week or a custom time) and be post-only; Open orders shows an Expires column. App-run take-profit/stop-loss and TWAP rules (off unless `AUTOMATION_ENABLED=true`; `AUTOMATION_FILE`): an Automate panel on the event page, an `/automation` page with pause/resume and cancel, and a header link. Rules place market orders through the same server checks, only while the app runs, and every restart begins paused.
- Fix: the ticket's post-only and price checks now pick the best bid/ask by value (book levels arrive worst-first).
- Project docs: phased plan, state tracker, external facts (verified 2026-11-13), hazards, agent
  instructions.
- Phase 0 slice A: app scaffold (Next.js, Node 24), env validation, Host/Origin middleware, `/api/access`, access badge, `npm run doctor`, client-bundle secret scan.
- Access badge uses Polymarket's API jurisdiction rules instead of the geoblock `blocked` flag, which only describes the website (IE, JP, NL, KR can trade via API).
- Phase 3 slice D: trade ticket with confirm dialog, `POST /api/orders` and `DELETE /api/orders/[id]` with server-side validation (tick, min size, cap, held size, trading mode), cancel button, market names in open orders and trade history.
- Phase 1 slice B: wallet dashboard (balance, portfolio value, PnL, positions, open orders, trades, activity).
- Phase 2 slice C: search bar (URL, slug, id, condition id), event page with live order book.
- Market orders now pass `maxSpend` (fees can no longer exceed the per-order cap) and a 5¢ worst-price bound.
- Dashboard shows an **Enable trading** notice when the wallet lacks its trading approvals; `GET/POST /api/approvals` checks and submits them after confirmation. README covers funding through the Polymarket bridge.
- Enable trading now works with a Relayer API key (`POLYMARKET_RELAYER_API_KEY`, `POLYMARKET_RELAYER_API_KEY_ADDRESS`) and explains when it is missing; new `POLYGON_RPC_URL` (default publicnode) because the SDK's default RPC rejects large batches; rejection logs include Polymarket's status and message.
- Phase 7: Redeem button on resolved positions and a "claim winnings" banner (`POST /api/redeem`, gasless via the relayer key); Cancel all open orders on the dashboard and per event (`DELETE /api/orders`); browser-only price alerts with notifications or in-page toasts, an Alerts page and header count (`/api/prices`).
- Event page: price chart for the selected outcome (1H/6H/1D/1W/1M/MAX, hover, change over range), live order book over Server-Sent Events with a polling fallback, and a live trade tape (`/api/history`, `/api/stream`). Single-market events open with that market selected.
- Browse home page: trending, new and ending-soon events, eight categories, keyword search from the header (`/api/events`, `/api/categories`, `/api/search`); recurring up/down events excluded via Polymarket's own tags. The wallet dashboard moved to `/portfolio`.
- Event page: "Your orders" strip lists open orders on that event with Cancel (polls every 10 s).
- Enable trading re-reads the approval state for up to ~12 s after submitting, so it no longer reports approvals as missing while the state catches up.
- Fix: dashboard open orders, trades, activity and positions were always empty (SDK `.from(undefined)` returns an empty page).
- MIT license; README disclaimer.
- README: step-by-step setup for other users (env variables, Relayer API key, funding via the bridge, enabling trading) and a troubleshooting table.
- Event page hides inactive placeholder outcomes behind a toggle; outcome list scrolls; ticket no longer requests a book before a market is selected.
